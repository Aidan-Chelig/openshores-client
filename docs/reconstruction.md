# Reconstruction ledger

## Scope

Build a Rust client interoperable with the supplied OpenShores server. Start
with transport and login, then reconstruct asset loading, scene state, and the
playable client. A full game reimplementation spans many milestones.

Bevy is the preferred 3D renderer and GPUI is an undecided UI candidate. Preserve
the original OpenShores interactions; see [experience fidelity](experience.md).

## Evidence established

- `reference/OpenShores-server` includes Python source for account handling,
  networking, protocol codecs, gameplay, world simulation, and persistence.
  Source availability makes this the primary protocol reference.
- `reference/openshores-full` includes the Windows client, Qt5, SDL2, OpenAL,
  game data (`GD`), textures, blueprints, and resource libraries.
- `reference/OpenShores-1.0.0-to-1.0.2` and `reference/OpenShores-patch` provide
  additional builds; their differences have not yet been investigated.
- REA `inspect_pe_resources` identifies the full-build `OpenShores.exe` as
  PE32+, 51,135,102 bytes, SHA-256
  `285047485af36d98bc9fe3c1c0a1f7bed4693f7ef3abcafc2c6d39d5e0d81d80`.
  Resource coverage: 21 directory entries and 9 resources, complete within the
  operation's scope. Evidence:
  `ev_b97bf5f74266a40064c6806b9e8848f0be58cbc906cc624b44a30e776ccd2442`.
  This inventories resources; it does not establish client runtime behavior.
- `protocol/framing.py`: 1–4 byte length prefix, top two bits encode the
  number of following bytes, maximum payload length `0x3fffffff`.
- `protocol/stream.py`: big-endian integers, QString as a byte length followed
  by UTF-16BE, `0xffffffff` as null. Empty and null are distinct.
- `protocol/encryption.py`: version `13.110.60`, base key `0x6e31`, reversible
  byte obfuscation. This is not secure encryption.
- `core/config.py`: separate login/chat/scene/mail ports 16757–16760.
- GD layouts differ: `openshores-full/GD` is 328,457 bytes, while
  `OpenShores-server/GD` is 403,888 bytes. The server construction-table offset
  397,280 cannot apply to the full-client file.

Paths above are relative to `reference/OpenShores-server/src/openshores` unless
explicitly prefixed. Server source establishes server expectations; original
client behavior still needs corroboration for compatibility edge cases.

## Milestones

1. Transport foundation: implemented length framing, bounded payload reads,
   Qt byte/string decoding, key derivation, and byte obfuscation. Tests cover
   length thresholds, invalid input, Unicode, and concatenated packets.
2. Login: implemented request encoding, success/failure/redirect/version reply
   decoding, six-slot roster, and a bounded TCP exchange. The password field is
   SHA-1 of UTF-8 input (`core/accounts.py::_wire_password`); the library takes
   the precomputed 20-byte digest or `wire_password` helper. The CLI reads a
   hidden password, hashes UTF-8 verbatim, and displays populated roster slots
   with their original slot numbers. Username encoding follows the server's
   Latin-1-first decoder; wider Unicode usernames remain unsupported.
   A roster fixture was generated directly by the Python server's
   `build_login_ok_reply_for_avatars(42, [(42, "Explorer 🚀", bytes(range(24)), 1, True)])`.
   Tests decode that fixture and verify the entire request across a fragmented
   localhost mock-server exchange. `tests/reference_interop.py` additionally
   checks the executable against the Python request parser and reply builders,
   covering populated/empty rosters, both account rejection reasons, redirect,
   version mismatch, and an unknown opcode. Full local reference-server
   authentication is now verified with a synthetic account and PostgreSQL.
   An explicit roster avatar ID drives the local scene probe; graphical
   password entry/selection remain unfinished.
3. Assets: implemented the server GD construction-table reader, validated
   against all 83 Python-decoded rows (ID, name, industry, terrain, radius).
   It rejects incompatible layouts. Client GD, HAR, blueprint, texture, and
   model formats still require source inspection and focused binary analysis.
4. First rendered scene: choose the renderer after establishing scene/data
   requirements, then load a real reference asset and reconstruct world state.
5. Playable slice: avatar selection, scene connection, movement, terrain,
   camera, chat, and incremental scene updates.
6. Expand feature coverage against an explicit gameplay checklist and reference
   behavior, including crafting, buildings, vehicles, and persistence.

## Scene bootstrap progress

`src/scene.rs` implements client resume hello and active-unit selection encoders,
plus server world redirect, active-unit confirmation, initialization, scene
manifest, and heartbeat decoders. Fixtures are generated by or parsed with the
reference server. Platform/session fields in the hello are explicit caller
inputs; test values are synthetic and do not establish the original client's
platform encoding.

Sources: `protocol/scene_parse.py::_parse_scene_0x38`,
`protocol/scene_init.py`, `network/scene/bootstrap_flow.py`,
`network/scene/manifest.py`, and `network/scene/ticker_c2.py`.

The initial scene connection may receive a `0x22` world redirect; subsequent
connections process `0x38` resume or `0x3b` selection before pushing world state.
Connection gating in `network/scene/connection.py` and `conn0.py` means a live
driver must track reconnection state. `src/local_scene.rs` now performs this
flow for loopback development servers, retaining the original scene socket
through bootstrap to avoid premature per-IP session cleanup.

Opcode context matters: client `0x38` is resume, server `0x38` is initialization;
server `0x22` can be a redirect during initial connection or building data in
world traffic. The separate decoders do not classify arbitrary packets by
opcode alone. Atom prefixes are now decoded for the source-established kinds
listed below; unsupported packets and remaining body fields stay opaque.

## Full local-server integration

`tests/local_server.py` boots the unmodified reference server from an owned
temporary working directory with a disposable PostgreSQL cluster and synthetic
account/avatar. It applies the reference migrations and world generator, then
tests the Rust executable through authenticated login, scene redirect/resume,
active-unit confirmation, initialization, chat ACK, and scene manifest.

Observed successful run: avatar 512, 49 manifest atoms, 9,663 inbound scene
packets, 424,062 payload bytes. The capture was reread using Python's framing
decoder, and its final manifest included the selected avatar. Counts describe
this synthetic test world, not all possible worlds or builds.

The server waits for a chat `0x0b` packet with avatar ID at byte offset 9 before
releasing the post-login manifest. Source: `network/chat_channel/connection.py`
and `network/scene/connection.py`. The local probe supplies account fields from
the world redirect; their meaning and original client platform constants remain
unverified beyond successful local interoperability.

The reference init builder defaults to chat port 16758 even if deployment uses
another port. The local probe supports an explicit chat-port override. This
does not modify the reference source.

Testing policy: use synthetic loopback listeners or the reference server.
Do not contact the public OpenShores service. The local scene driver rejects
external endpoints and redirect hostnames without DNS or connecting. Packet,
byte, and elapsed-time limits bound the probe. Unknown packet payloads are
retained for offline reconstruction.

## World model and offline replay

`src/world.rs` handles common atom prefixes for universe, galaxy, sector,
solar system, star, globe, gas giant, ring, ring section, person, vehicle, and
building packets. Flags `0x01`, `0x02`, `0x04`, and `0x08` supply parent,
creation time, modification time, and six transform floats respectively.
Higher flag bits are retained without assigning undocumented semantics.

Source evidence: `protocol/atoms/base_update.py`,
`protocol/atoms/person.py`, `gameplay/native_atom.py`,
`gameplay/vehicles/atom_packet.py`, `gameplay/dabd_frame.py`, and the
`atoms_c2`/sibling builders in `network/scene/connection.py`.

Sector and solar-system QString names, named unit prefixes, and the
flag-0/flag-1 WgWorld zone/orbit/name prefix are decoded. The entire atom body
is also retained. Sources: `gameplay/world_body.py` and
`protocol/atoms/galaxy_rename.py`. No complete creature, vehicle, building,
world terrain, or model decoder is claimed.

State applies updates in receive order, preserves omitted values, distinguishes
omitted and explicit null names, and permits parents to arrive later. Known
parent cycles and atom-kind conflicts are rejected before mutating state.
Clock ordering, deletion semantics, and type changes are not yet established
against original-client behavior. Manifest visibility is independent of the
cache; leaving a manifest does not erase cached identity.

Raw positions and rotations retain their wire values. Rotations have not been
converted to Bevy quaternions, and relative transforms have not been composed.
Source routines use different coordinate contexts; guessing a global unit or
angle convention would risk changing the original experience.

`inspect-scene` replays an existing scene capture offline with bounded frame,
packet, and total-byte sizes. It reports entity kinds, names, transforms,
unresolved parents, missing manifest IDs, and the selected avatar's ancestry.

Verified full local-server run: 49 decoded entities, all 49 manifest identities
present, no unresolved parents; 1 universe, 1 galaxy, 27 sectors, 1 solar
system, 1 star, 14 globes, 3 gas giants, and 1 person. The player chain resolves
as person -> globe -> star -> solar system -> sector -> galaxy -> universe.
Offline replay of the captured 9,663 packets produces the same complete
hierarchy. Game-data table packets remain opaque and counted separately.

Unit tests cover a Python-generated sector and sparse rename, hierarchy cycles,
kind conflicts, manifest/cache independence, and truncated captures. The
reference interoperability script rechecks the sector fixtures against the
actual Python builders; the full-server harness verifies offline replay.

## Globe surface and base terrain

`WorldState` now reads the globe class flag-1 fields: size, atmosphere type,
atmosphere density, water, and six big-endian float terrain parameters. Sparse
rename updates preserve those fields. Other class payloads remain retained as
raw body bytes. Source: `gameplay/world_body.py::_build_wg_body`.

`src/terrain.rs` ports `protocol/rng.py::AuNoise` and
`gameplay/worldgen/terrain.py::terrain_altitude_msl`: wrapping 32-bit integer
hashes, cosine interpolation over cubic-smoothed coordinates, seven octaves,
dateline/pole blends, relief shaping, and size-dependent altitude scale.
The six parameters retain their serialized f32 values while sampling uses f64,
matching the reference's numerical path. Computed heights match Python within
1e-8 at 32 fixed coordinates and 56 coordinates across all 14 local-server
globes. Cases include negative noise offsets, small/large worlds, signed relief,
the dateline, and both poles.

The reference radius is `size * (1000 / 1.609344 * 5)`.
`surface_position` uses a Z-polar sphere consistent with `city_model.py`'s
latitude/longitude conversion. Inputs use radians in the library and degrees
in `sample-terrain`. This reproduces reference numeric conventions, not a new
unit or axis convention for Bevy.

Geological deformation, road deformation, vegetation, water surfaces, ring terrain,
client mesh resolution/LOD, and renderer coordinate conversion are unfinished.
Do not treat the base terrain sample as the final collision/rendering surface.

`src/geology.rs` decodes the nine natural-feature layouts in
`gameplay/worldgen/geology.py`: valley, crater, mesa, volcano, river, chasm,
henge, vent, and fissure. GlobeLLF serializes longitude before latitude;
henge slabs are signed bytes. Source parameters retain their a/b/c/d ordering
without inventing physical semantics. Globe class flag-8 supplies the feature
count and records; sparse omission preserves previous geology while an explicit
zero count clears it. Roads and other unknown kinds stop prefix decoding, since
records are not length-prefixed. The complete original body remains retained,
including unsupported records and subsequent DNA/flora/home fields. CLI replay
reports decoded count, declared count, and the first unsupported kind.
Tests cover all nine record boundaries, truncation, signed fields, coordinate
order, unsupported types, and sparse-state clearing/preservation. These records
do not yet alter the base terrain sampler.

`src/qt_resources.rs` reads the supplied symbol-bearing PE/COFF layout without
loading code. It pairs repeated data/name/tree triplets, maps section-relative
symbol values to file bytes, bounds each array by neighboring symbols and
section size, and traverses version-specific Qt tree records. Names, child
indices, flags, locale fields, and payload lengths follow
[Qt's resource implementation](https://raw.githubusercontent.com/qt/qtbase/5.15/src/corelib/io/qresource.cpp).
File identity includes pool, path, country, and language; no locale precedence
or cross-pool override behavior is assumed. The caller supplies the established
resource version. Zlib uses the bounded, checksum-validating qCompress decoder;
zstd is explicitly unsupported.

Validated inventory: 446 entries, 40,143,188 decoded bytes: 167 PNG, 33 BMP,
41 `.3ds`, 139 `.3dsN`, 34 `.3dsX`, and 32 `.SoH` paths. Those extensions are
inventory facts, not proof that the variants are standard 3DS geometry.
`tests/reference_models.py` independently uses GNU objdump for COFF locations,
Python struct/UTF-16 for tree decoding, and Python zlib for compressed payloads.
It compares all metadata and verifies total decompression, then extracts one
file of each extension byte-for-byte and checks PNG/BMP signatures. Existing
outputs and mismatched pools are rejected. Rust synthetic tests cover truncated
images, cycles, child/data bounds, invalid UTF-16/path names, unsupported flags,
and invalid COFF sections/auxiliary counts. No reference assets are modified
or copied into the repository as fixtures.

Limitations: this is a source-profile reader, not a general PE loader; resource
arrays in stripped/differently organized DLLs are unsupported. See the following
raw geometry decoder for the supported 3DS-family layouts. Original render
coordinate conversion, material rules, and `.SoH` structure remain unresolved,
as does the Bevy renderer.

### Raw 3DS-family geometry

`src/model.rs` reads the chunked `.3ds`, `.3dsN`, and `.3dsX` resources without
loading executable code. Chunks have little-endian u16 IDs and u32 total byte
lengths. The root is `0x4d4d`, editor `0x3d3d`, named object `0x4000`, mesh
`0x4100`, vertex list `0x4110`, face list `0x4120`, material assignments `0x4130`,
UV list `0x4140`, smoothing masks `0x4150`, and local matrix `0x4160`. Ordinary
layouts are cross-checked against
[Assimp's importer](https://raw.githubusercontent.com/assimp/assimp/master/code/AssetLib/3DS/3DSLoader.cpp).
This is an independent bounded reader, not an integration of Assimp rendering.

GNU objdump static disassembly of `OpenShores.exe` establishes the variant
selection in `Au3dsGLSLModel::Load(QFile&, double)` at VA `0x1413a6620`:
`.3dsX` selects MODEL_TYPE 3, `.3dsNT` selects 2, `.3dsN` selects 1, otherwise 0.
Referenced strings are at VAs `0x1422cf22d`, `0x1422cf233`, `0x1422cf23a`.
`Au3dsGLSLObject::LoadFaceListChunk` at `0x1413a3e00` reads three u16 vertex
indices and a u16 flag. Types 1 and 2 additionally read nine floats; type 2
then reads ten more. Types 0 and 3 use the ordinary eight-byte face record.
This establishes the 44-byte N records versus eight-byte standard/X records.
The supplied model DLL has no `.3dsNT` inventory; that variant is not supported.
Extra N floats retain their wire order with no assumed shading semantics.

These function observations are from GNU disassembly, **not REA decompilation**:
Ghidra's initial main-executable analysis exceeded the MCP's 300-second tool
deadline; a targeted face-loader dossier request also timed out. The native
session was subsequently closed successfully. REA open establishes artifact
identity only: SHA-256
`285047485af36d98bc9fe3c1c0a1f7bed4693f7ef3abcafc2c6d39d5e0d81d80`.
No runtime behavior was observed and no original client was executed.

The decoder keeps vertex coordinates, matrix values, UVs, face flags, smoothing
masks, material assignments, material names and texture filenames unchanged.
Names retain raw bytes; CLI display uses lossy UTF-8 only for readability.
Unknown chunks (including keyframes and unimplemented material controls) retain original
file ranges backed by the complete model bytes. No transform, axis swap,
winding change, normalization, master-scale application, smoothing computation,
texture lookup, or keyframe evaluation is performed.

Independent Python raw-byte geometry decoding matches every Rust geometry
digest for 209 models: 618 meshes, 91,638 vertices, and 126,800 faces. The digest
is SHA-1 for parity, not authenticity; it includes names, positions, indices,
flags, N extensions, UVs, matrices, smoothing masks, and face-material groups
in source order. `tests/reference_geometry.py` documents that serialization.
162 meshes contain unequal UV and vertex counts. These are preserved without
inventing a repair or claiming how the original client maps them.

Five `.3ds` resources have root sizes larger than their extracted payloads:
`mRocketShip` (90,955 vs 4,053), `mHitSeed` (2,540 vs 1,696), `mNeptune`
(441,834 vs 2,654), `mHitPierce` (1,958 vs 1,618), and `mHitSlash`
(1,957 vs 1,617). Strict decoding rejects them; the original client's handling
and whether those size fields are stale remain unresolved. `verify-models`
continues scanning, reports all failures, and exits nonzero when any resource
is rejected. `.SoH` payloads remain opaque.

Synthetic tests cover all three supported variants, every truncation boundary,
opaque retention, wrong variants, invalid indices/material assignments,
non-finite fields, malformed chunk lengths, names, duplicate empty lists,
and chunk-budget exhaustion. Input (64 MiB), element (one million), chunk
(100,000), name, and depth limits bound allocation and traversal.

### Raw material records

`Material` now retains ordered ambient/diffuse/specular color records,
integer/float amount records, the two-sided chunk's presence, and the shading
word. Color parents `0xa010/0xa020/0xa030` contain `0x10` (three f32), `0x11`
(three bytes), or `0x12` (three linear-color bytes). Multiple representations
are kept independently, without choosing a renderer color or gamma conversion.
`0x13` and other unsupported encodings remain opaque.

GNU objdump disassembly of the same executable's
`Au3dsGLSLMaterial::LoadColorChunk` at `0x141394bc0` confirms those three
recognized IDs. Byte colors target separate QColor slots for `0x11` and
`0x12`; no original QColor/shader selection semantics are claimed here.
`LoadAmountChunk` at `0x141394a30` recognizes `0x30`, reading a u16 when the
chunk is eight bytes or MODEL_TYPE is 3, otherwise reading four bytes as an
f32. This differs from treating every `0x30` payload as an integer percentage.
The reader supports exact two-byte payloads and, outside X, exact four-byte
payloads; other lengths are rejected rather than tolerated as the original
code's loose bounds might permit. Amount parent IDs `0xa040/0xa041/0xa050/
0xa052/0xa053` remain explicit. No division by 100, opacity inversion,
shininess remapping, clamping, or Bevy material conversion occurs.

The ordinary color, shading and two-sided layouts are independently documented
in [Assimp's importer](https://raw.githubusercontent.com/assimp/assimp/master/code/AssetLib/3DS/3DSLoader.cpp).
This comparison establishes format fields, not equivalence between Assimp and
OpenShores rendering. A focused REA CLI attempt on the original color loader
was limited to 180 seconds and timed out (exit 124), without yielding successful
decompilation Evidence. No MCP configuration was changed and no target code
was executed.

`tests/reference_geometry.py` independently parses raw material bytes and
matches all material SHA-1 fingerprints across the same 209 decodable models:
297 materials, 1,041 color records, 250 integer amounts, and 384 float amounts.
The separate material fingerprint includes names, texture filenames, ordered
color/property/encoding records, amount/property/width/value records, two-sided
presence, and optional shading. Existing geometry fingerprints remain unchanged.
`inspect-model` prints these records; `verify-models` reports both fingerprints.
Synthetic tests cover source order, multiple color encodings, opaque retention,
both amount widths, X rejection of float amounts, malformed lengths,
non-finite values, and duplicate shading.

Remaining renderer obligations: choose/apply original color representations,
establish normal-extension semantics and generated smoothing behavior, resolve
texture names/overrides, explain unequal UV counts, and reproduce material
conversion and coordinate transforms before claiming visual fidelity.

### Offline geometry inspection exports

`src/model_preview.rs` adds two diagnostic exports from the already-decoded
geometry, independent of Bevy or GPUI. `export-model INPUT NEW.obj` writes
raw `v` coordinates and triangle `f` indices with cumulative one-based offsets
across named mesh groups. Generated object identifiers prevent model names
from injecting directives. f32 shortest decimal formatting preserves position
bits on round-trip, including negative zero. Winding and source mesh order
remain unchanged. The basic OBJ position/index convention is cross-checked
against [Blender's exporter](https://raw.githubusercontent.com/blender/blender/main/source/blender/io/wavefront_obj/exporter/obj_export_file_writer.cc).

`preview-model INPUT NEW.svg` produces three orthographic wireframe panels for
raw X/Y, X/Z, and Y/Z. The panel layout, uniform fitting, colors and typography
are debugging design choices, not reconstructed OpenShores UI. Model bounds
use f64 to keep projections finite for extreme f32 inputs and zero-sized spans.
Coordinates in SVG paths are rounded to three decimal places. Every triangle
is drawn in each panel, with no depth ordering, occlusion, lighting or materials.
No untrusted model strings, scripts, external references or textures enter SVG.

Both exports omit original local matrices, master scale, normals, smoothing,
UVs, materials and keyframes, and are explicitly labeled as raw-geometry
diagnostics. They do not resolve the remaining fidelity obligations and must
not be presented as the original renderer. CLI outputs use create-new files
and report write/flush errors; a failed write can leave a partial new output.
Invalid source decoding occurs before any output is created.

`tests/reference_preview.py` independently checks every export across all 209
valid models: OBJ coordinates round-trip byte-exactly, global indices/winding
and mesh grouping match source data, and all SVG path coordinates agree with
Python orthographic projections within rounding tolerance. Existing output
files remain unchanged on retry; malformed inputs create no outputs. Rust
tests cover cross-mesh offsets, negative zero, empty and coincident geometry,
extreme finite coordinates, invalid indices/non-finite positions, untrusted
names, and writer failures. The previous five invalid-root models remain
rejected. `inspect-model` now displays UV counts rather than just presence,
and reports the raw-coordinate bounds.

### Structural model audit

`src/model_audit.rs` and `audit-model INPUT` inspect already-decoded geometry;
this is diagnostic implementation work, not new binary/runtime evidence.
Material group names match raw material-name bytes exactly. Missing and
duplicate names remain visible rather than selecting a default or first match.
Face-assignment occurrence counts report uncovered and overlapping assignments.
Vertices referenced by faces, repeated triangle indices, and f64 zero cross
products provide raw-coordinate degeneracy diagnostics.

Edges use unordered original index pairs, counting distinct incident faces;
self-edges are omitted and each triangle contributes at most once to an edge.
One incident face is reported as a boundary, more than two as nonmanifold.
These are **index topology**, not welded geometric topology or a collision
verdict. Split positions/texture seams can create apparent boundaries; the
audit never merges vertices, changes winding, removes faces, or computes
normals. UV counts and extension presence are metadata only, not proof of their
mapping or shading semantics. Geometry validation and a three-million-work-unit
budget bound traversal and allocation, including manually constructed models.

Python independently matches all audit fields across all 209 valid models and
618 meshes. Aggregate observations: 64 unreferenced vertices, five triangles
with repeated indices, 142 f64-zero-area triangles, 49,228 raw-index boundary
edges, and 157 edges with more than two incident triangles. All faces have one
material-group assignment; there are no missing or ambiguous referenced
material names in this inventory. 79,666 faces have N-extension records.
The same five invalid-root models remain rejected before auditing.

Synthetic tests cover ambiguous/missing names, overlapping/unassigned faces,
repeated indices, unused positions, per-triangle edge deduplication, invalid
material face references, empty models and assignment-budget exhaustion.
The audit does not mutate the decoded model, preview/export, or reference data.

### Optional interactive Bevy inspector

`viewer` is an opt-in Cargo feature; default/headless builds do not compile Bevy.
`view-model INPUT` decodes a local supported model before starting the Rust
window and has no login/network path. Bevy 0.19.1 is pinned because its declared
MSRV matches Rust 1.95. Bevy 0.20's declared MSRV is 1.97.1, so the existing
toolchain was preserved rather than upgraded for this diagnostic tool. The
viewer uses only the required app, window, rendering, mesh/material, gizmo and
X11/Wayland features—no audio, GPUI, remote plugins or external scene assets.

`src/viewer.rs` creates a display-only copy, centering with f64 bounds and
uniformly fitting the largest raw-axis span to two units. Source geometry,
triangle order and indices are unchanged. Raw axes are retained; the Z-up orbit
camera, distance limits and controls are diagnostic design choices. The default
is now a neutral double-sided physically based material (roughness 0.55,
metallic 0), ambient light, a shadow-casting directional key and a cool fill.
Reinhard tonemapping is used in lit mode; `--unlit` or L selects unlit rendering
with no tonemapping. These choices do not interpret source materials, UVs,
normals, smoothing or animation and do not claim original shading fidelity.
Each display triangle is expanded to three vertices with a winding-derived
flat normal, calculated with f64 intermediates. Degenerate triangles remain
present with a finite Z normal fallback. Source geometry is never rewritten.
Mesh transforms/master scale and original shaders remain unapplied.

Controls: left-drag orbit, line/pixel-aware wheel zoom, W wire toggle, L lighting
toggle, R camera reset (preserving lighting/wire modes),
Escape quit. The window title identifies the raw-geometry inspector and shows
those controls. Optional `--smoke-frames N` (1..=3600) exits after N application
updates; these are not necessarily presented graphics frames. Invalid limits
are rejected before creating the app, and failure exits propagate.

Verification: full viewer-enabled build/tests/Clippy succeed. CPU tests check
normalization at extreme finite source coordinates, source/index preservation,
invalid input, and ECS mesh/material/camera setup without a window/GPU. A
bounded SUV smoke run opened the local window using Vulkan on the AMD Radeon
AI PRO R9700 (RADV GFX1201, Mesa 26.2.4) and exited normally. The driver emitted
its existing non-conformance/testing warning. This establishes initialization
and bounded execution, not pixel parity or manual verification of every control.
No original executable was run and no OpenShores server was contacted.

The mesh/camera integration follows the selected Bevy crate's official custom
mesh/orbit examples; the original OpenShores rendering obligations remain
separate. This is not a claim that a diagnostic camera/shader reproduces the
game experience.

Modern lighting is explicitly permitted while faithful shading is deferred.
Normal-generation tests cover opposite windings and degenerate triangles;
CPU-only ECS tests exercise lit/unlit material switching. CLI tests cover flag
ordering, duplicate options and bounded smoke limits. Lighting integration uses
the [official Bevy 0.19.1 lighting example](https://github.com/bevyengine/bevy/blob/v0.19.1/examples/3d/lighting.rs).
All 41 viewer-enabled tests and 37 default/headless tests pass, as do both
Clippy configurations. Bounded local GPU runs in lit and unlit modes exit
successfully; this is a renderer smoke check, not a visual-fidelity assertion.
